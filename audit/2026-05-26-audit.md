## 1. Security

### 1.1 🔴 CRITICAL — Zapier chatbot: внешний скрипт без SRI, без CSP ограничения

**Файл:** `index.html:22-23`

```html
<script async type='module' src='https://interfaces.zapier.com/assets/web-components/zapier-interfaces/zapier-interfaces.esm.js'></script>
<zapier-interfaces-chatbot-embed is-popup='true' chatbot-id='cmftsrve4001a10558q2960z1'></zapier-interfaces-chatbot-embed>
```

Проблемы:
- **Supply chain risk**: скрипт подгружается с CDN Zapier без `integrity=` (SRI). Если Zapier будет скомпрометирован, атакующий получит полный доступ к DOM страницы — тот же origin, что и основное приложение.
- **Chatbot ID раскрыт публично** в HTML. Если у Zapier нет origin-ограничений, бот может быть встроен кем угодно.
- **CSP**: нет `Content-Security-Policy` заголовка вообще (ни в `index.html`, ни в `vite.config.ts`). Без CSP любой XSS получает полный контроль над страницей.
- Атрибут `async` на `type="module"` является no-op — ES-модули всегда загружаются асинхронно, но это сигнал о том, что автор не проверял этот код.

**Рекомендация:** Добавить CSP через nginx (минимум `script-src 'self' https://interfaces.zapier.com`). Рассмотреть замену Zapier виджета на self-hosted чат или виджет с iframe-изоляцией.

### 1.2 🔴 CRITICAL — postMessage без проверки source и без ограничения origin при получении

**Файл:** `src/views/Admin.vue:108-111`

```ts
const adminWindow = window.open('https://admin.organization2025.com/admin/login', '_blank');
setTimeout(() => {
    adminWindow?.postMessage(post_data, 'https://admin.organization2025.com');
}, 1000);
```

Проблемы:
- **Timeout-based синхронизация ненадежна**: `setTimeout(..., 1000)` — это гонка состояний. Если `admin.organization2025.com` загружается дольше 1 секунды (медленная сеть, cold start), `postMessage` уйдет в никуда — токен не передастся, или, что хуже, будет принят другим обработчиком.
- **JWT-токен, username и другие credentials отправляются через postMessage** в открытое окно. Если на `admin.organization2025.com` есть любой XSS — атакующий перехватывает токен через `window.addEventListener('message', ...)`.
- `post_data` включает `...result.data` — полный ответ бэкенда, что может содержать избыточные данные.
- Нет проверки `adminWindow` перед использованием (только optional chaining, но нет fallback если window не открылся — например из-за popup blocker).

**Рекомендация:** Этот паттерн передачи авторизационных данных через `postMessage` является архитектурной проблемой. Авторизацию должен делать сам admin-домен (SSO/OAuth/redirect flow), а не публичный сайт. На минимуме — убрать `setTimeout`, использовать `onload`/`load` event.

### 1.3 🟠 HIGH — XSS через v-html с пользовательскими данными в sendMail

**Файл:** `src/service/global.ts:15-44`

```ts
export const sendMail = async (data: any) => {
    let emailBody = "<div>";
    // ...
    emailBody += `<a href="tel: ${data.phone}">${data.phone}</a>`;
    emailBody += `<span>${data.name}</span>`;
    emailBody += `<span>${data.org}</span>`;
```

Данные из пользовательских форм (`name`, `phone`, `org`) **конкатенируются напрямую в HTML-строку** без какого-либо escaping и отправляются на бэкенд. Это XSS в email (email client может рендерить HTML). Если бэкенд когда-либо отображает это письмо в web-интерфейсе без санитизации — это полноценный stored XSS. Кроме того, `data.phone` используется в `href="tel: ${data.phone}"` — инъекция возможна через `javascript:` схему у некоторых email-клиентов.

**Рекомендация:** Добавить HTML escaping для всех user-controlled значений перед вставкой в HTML:
```ts
const escape = (s: string) => s.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;').replace(/"/g,'&quot;');
```

### 1.4 🟠 HIGH — v-html из translations: потенциальный XSS если translations скомпрометированы

**Файлы:** `src/views/Index.vue:8,10,18,...` (161 использование `v-html` с `t(...)` по всему приложению)

`v-html` с `t('...')` используется везде. Хотя содержимое JSON-файлов контролируется командой, это создает риск при:
- компрометации CI/CD pipeline
- XSS через подмену lang-файлов
- ошибочном добавлении `<script>` тега в перевод

Особо критично в `Footer.vue:20`: `v-html` на `<a>` — `href` берется из `t('footer.btn_1')`, что означает потенциальный open-redirect через i18n.

**Рекомендация:** Для статических переводов с разметкой (`<b>`, `<br>`) использовать `vue-i18n` `<i18n-t>` component с named slots вместо `v-html`. Это позволяет использовать разметку без риска XSS.

## 2. TypeScript

### 2.1 🔴 CRITICAL — tsconfig.app.json: strict mode полностью отсутствует

**Файл:** `tsconfig.app.json`

```json
{
  "compilerOptions": {
    "resolveJsonModule": true,
    "esModuleInterop": true,
    "noEmit": true,
    "skipLibCheck": true
  }
}
```

Нет `"strict": true` и НИ ОДНОЙ из strict-опций (`noImplicitAny`, `strictNullChecks`, `strictFunctionTypes` и т.д.). Это означает, что TypeScript фактически отключен как система типов. `vue-tsc` в CI успешно компилирует (`npm run build`) несмотря на ~40+ реальных ошибок типов, которые обнаруживает строгая проверка.

Подтверждение: запуск `vue-tsc` с правильной конфигурацией показал **40+ ошибок**.

---

### 2.2 🔴 CRITICAL — vue-tsc при сборке использует неустановленную глобальную версию

**Файл:** `package.json:8`

```json
"build": "vue-tsc -b && vite build"
```

`vue-tsc` в `devDependencies`, но `npm run build` в CI работает только потому что `vue-tsc` установлен локально. При чистой среде (`npm ci` на CI) — команда разрешается в глобальную или через `npx` (другой версии). Это уже проявляется: при тестировании `npx vue-tsc -b` установилась версия `3.3.2` вместо `^3.1.1` из package.json.

**Рекомендация:** Заменить на `npx --no -- vue-tsc -b` или использовать `./node_modules/.bin/vue-tsc -b`.

### 2.4 🟠 HIGH — `ref(null as string)` — неверный тип

**Файл:** `src/components/Footer.vue:91`

```ts
const phone = ref(null as string)
```

`null as string` — это приведение типа, которое говорит TypeScript: "доверяй мне, это string". Фактический тип будет `Ref<string>`, но начальное значение `null` — TypeScript ошибку не выдаст (из-за отсутствия strict), но runtime может сломаться. Правильно: `ref<string>('')` или `ref<string | null>(null)`.

## 3. Vue Best Practices

### 3.1 🟠 HIGH — Глобальные event listeners без cleanup в Header.vue

**Файл:** `src/components/Header.vue:54-71`

```ts
window.addEventListener('scroll', () => { ... });
document.addEventListener('click', (event: MouseEvent) => { ... });
```

Обе подписки добавляются **напрямую в `<script setup>`** (т.е. при каждом монтировании компонента) **без** соответствующего `onBeforeUnmount` cleanup. `Header` — это постоянный компонент в `App.vue`, он не размонтируется при навигации, так что при текущей архитектуре утечки нет. Но это хрупкий паттерн: если `Header` когда-либо вынесут в условный рендер — появится настоящая утечка памяти.

**Рекомендация:** Обернуть в `onMounted` / `onBeforeUnmount`:
```ts
onMounted(() => window.addEventListener('scroll', onScroll));
onBeforeUnmount(() => window.removeEventListener('scroll', onScroll));
```

---

### 3.2 🟠 HIGH — `useRoute()` вызывается внутри обычной функции (не в setup)

**Файл:** `src/components/Header.vue:101`

```ts
const getLangLink = (newLang: string) => {
  const route = useRoute();  // Called inside a regular function, not at setup() top level
```

Composables (`useRoute`, `useI18n` и т.д.) должны вызываться только на верхнем уровне `setup()`. Вызов внутри обычной функции нарушает правила Vue Composition API. Это работает в текущей версии Vue из-за того, что `getCurrentInstance()` доступен внутри событий, но это недокументированное поведение и может сломаться.

**Рекомендация:** Вызвать `useRoute()` на верхнем уровне `<script setup>` и использовать `route` через замыкание.

---

### 3.3 🟠 HIGH — animateCountUp: RAF не отменяется при unmount

**Файл:** `src/service/global.ts:81-93`

```ts
export function animateCountUp(el: HTMLElement) {
    // ...
    function update(now: number) {
        // ...
        if (progress < 1) { requestAnimationFrame(update) }
    }
    requestAnimationFrame(update)
}
```

Функция возвращает `void` — нет способа отменить анимацию. Если компонент размонтируется пока анимация выполняется (2000ms), RAF-колбэк продолжит работать и пытаться записывать в `el.innerText` уже несуществующего DOM-элемента.

**Рекомендация:** Возвращать `cancelAnimationFrame`-handle и сохранять его в `onBeforeUnmount`.

---

### 3.4 🟠 HIGH — v-for без `:key` на всех итерациях

**Файл:** Множество файлов, примеры:
- `src/components/Header.vue:5,13,27,32,33,38`
- `src/components/Footer.vue:27,34,40,69`
- `src/views/Index.vue:20,91,185,207,242`

Практически **все** `v-for` без `:key`. Это вызывает предупреждения от eslint-plugin-vue (правило `vue/require-v-for-key`) и потенциальные баги при перерендере — особенно когда переключается язык (список меняется).

**Рекомендация:** Добавить `:key` на каждый `v-for`. Для nav-items используй `item.link`, для lang — `lang`, для массивов с index — убедиться что порядок стабилен.

### 3.5 🟡 MEDIUM — `<script setup>` смешивается с code-at-module-level в MobileApp.vue

**Файл:** `src/views/MobileApp.vue:180-184`

```ts
// redirect to app by QR
if (window.location.search.includes('d=mobile')) {
  const userAgent = navigator.userAgent.toLowerCase();
  if (/android/.test(userAgent)) window.location.href = APPS[1].link;
  if (/iphone|ipad|ipod/.test(userAgent)) window.location.href = APPS[0].link;

```

Этот код выполняется при импорте модуля (не при монтировании компонента). В SSR-среде это сломалось бы немедленно (нет `window`). Даже для SPA — это вызовет redirect **до** того как Vue смонтировал компонент. Правильно: поместить в `onMounted` или `router.beforeEach`.

### 3.6 🟡 MEDIUM — Дублирование данных: Tariff data в Index.vue и Tariffs.vue

**Файлы:** `src/views/Index.vue:378-416` и `src/views/Tariffs.vue:71-109`

## 4. SEO

### 4.1 🔴 CRITICAL — `<html lang>` захардкожен как `"ua"`, не динамический

**Файл:** `index.html:2`

```html
<html lang="ua">
```

Для 8-языкового сайта `lang` атрибут **обязан** обновляться при смене языка. `"ua"` — это не валидный BCP 47 код (правильно: `"uk"` для украинского). Поисковики используют `lang` для геотаргетинга.

**Рекомендация:** В App.vue или router.afterEach обновлять `document.documentElement.lang = locale.value` (с маппингом `ua` → `uk`).

---

### 4.2 🔴 CRITICAL — Нет per-page `<title>` и `<meta description>`

**Файл:** `index.html:14`

```html
<title>Organization2025</title>
```

Единый захардкоженный title для всего SPA. Нет `<meta name="description">`. Нет `<meta property="og:title">`, `<meta property="og:description">`, `<meta property="og:image">`. Нет Twitter Card.

Для маркетингового сайта это **критическая** проблема SEO. Каждая страница в поиске будет показываться с одинаковым Title и без description.

**Рекомендация:** Использовать `@vueuse/head` или `@unhead/vue` для управления мета-тегами на уровне каждого view.

---

### 4.3 🔴 CRITICAL — Нет `<link rel="alternate" hreflang>` для multi-language

Для 8 языков обязательно указывать `hreflang` alternate links. Без них Google не знает о языковых версиях страниц и не будет правильно показывать их по geo-запросам.

Нужно в `<head>` каждой страницы:
```html
<link rel="alternate" hreflang="uk" href="https://organization2025.com/ua/..."/>
<link rel="alternate" hreflang="en" href="https://organization2025.com/en/..."/>
<!-- ... все 8 языков -->
<link rel="alternate" hreflang="x-default" href="https://organization2025.com/en/"/>
```

---

### 4.4 🔴 CRITICAL — Нет `<link rel="canonical">`

Без canonical поисковик может индексировать `/en/`, `/ua/`, `/de/` одну и ту же страницу как разный контент. Нужен динамический canonical для каждого locale.

---

### 4.5 🔴 CRITICAL — Нет `robots.txt` и `sitemap.xml`

**Файл:** `public/` — нет `robots.txt`, нет `sitemap.xml`

Для маркетингового сайта это базовые требования SEO. Без `sitemap.xml` Google медленнее обнаруживает страницы. Без `robots.txt` нет контроля над тем, что индексируется (например `/go` с таблицей реестра может не нужно индексировать).

---

### 4.6 🟠 HIGH — SPA без SSR: проблема для SEO индексирования

Весь контент рендерится JavaScript. Googlebot справляется с CSR-контентом, но другие поисковики (Bing, Yandex) — хуже. Для маркетингового сайта настоятельно рекомендуется SSR (Nuxt 3) или pre-rendering (vite-plugin-ssr, @prerenderer/vite-plugin).
